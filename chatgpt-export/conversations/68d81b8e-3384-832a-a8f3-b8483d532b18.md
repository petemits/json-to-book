# Step-by-step: launch a free VoIP MVP

### 1) Choose your service model (pick one for MVP)
- **App-to-app WebRTC (recommended for “free”):** calls stay inside apps/browsers and never touch the PSTN — zero recurring telco cost.  
- **SIP app-to-app (softphones):** also free for on-network calling.

### 2) Pick the core software (open-source options)
- **Asterisk** — the classic open-source PBX and dialplan toolkit (very flexible for SIP + WebRTC). citeturn0search7  
- **FreeSWITCH** — another industry-grade open communications core (good for scaling or media-heavy apps). citeturn0search1  
(You can start with one of these; both are well documented and free to run.)

### 3) Pick free hosting or run locally
- **Free cloud:** Oracle Cloud “Always Free” tier provides compute you can run 24/7 within limits (use it to host your Asterisk/FreeSWITCH VM). Read the limits carefully to avoid accidental charges. citeturn0search10  
- **Local hardware:** a Raspberry Pi (or spare PC) is fine for a tiny user base and learning; it’s one-time cost but no monthly fees.  
Recommendation for a no-cost start: sign up for Oracle Free Tier, deploy a small Debian/Ubuntu VM, and install Asterisk or FreeSWITCH there.

### 4) Install and configure the PBX (MVP config)
A condensed checklist you can follow:

- Install prerequisites and PBX (follow official docs from Asterisk / FreeSWITCH). citeturn0search7turn0search1  
- Open only required ports in the VM firewall (and ideally front with a cloud firewall): SIP/TCP-TLS (5061), SIP/UDP (5060) *only if you need it*, and RTP UDP range (commonly 10000–20000). (If using WebRTC, you’ll also enable secure websockets/WSS and HTTPS.)

### 5) Choose softphone / client for users (free)

### 6) Secure the system (must do before opening to public)
- **Always use TLS for signaling** and **SRTP for media** to encrypt calls. Enforce strong authentication (unique passwords, no “1000/1000” defaults). citeturn1search0

- An **extension** is just a unique ID inside your PBX (for a user, phone, or softphone).  
- A **SIP account/endpoint** (username + password) gets tied to that extension.  
- You can assign “numbers” to those extensions however you like — often you make the **extension number equal to the SIP username** (e.g., extension **1001** is also SIP user **1001**).  

So:  

- If you set up **extension 1001** in Asterisk/FreeSWITCH, then you can register a SIP softphone with username = **1001**, password = (what you set), and it will map 1:1.  
- Inside the PBX dialplan, dialing **1001** rings that SIP device.  
- You can also give an extension multiple aliases (e.g., internal extension 1001, but reachable externally by a DID like +14165551234 once you connect to a SIP trunk).  

🔑 Important detail:  
- You can’t “duplicate” the exact same extension number for multiple SIP accounts unless your PBX supports multiple registrations per extension (Asterisk does, FreeSWITCH too). That way, **several devices can all be logged in as 1001** and they’ll all ring when someone dials 1001.  
- But **each extension number must be unique** inside the PBX — you can’t have two different users both called 1001.

# 🔹 What is WebRTC?
**WebRTC** is a set of open standards (backed by Google, Mozilla, W3C, and IETF) that allow browsers, mobile apps, and desktop apps to do **real-time peer-to-peer communication** (voice, video, data) without requiring plugins.  

So instead of installing a softphone app, a user can just open a web page and instantly make a voice/video call.

---

# 🔹 Key Components
1. **Media Capture**  
   - WebRTC uses built-in browser APIs to access microphone, camera, or screen.  
   - Example: `navigator.mediaDevices.getUserMedia({ audio: true, video: true })`

2. **Peer-to-Peer Connection (PeerConnection)**  
   - WebRTC tries to connect **two clients directly** (browser-to-browser, or browser-to-server).  
   - Uses ICE (Interactive Connectivity Establishment) to discover the best path.

3. **Signaling** (Not defined by WebRTC itself)  
   - WebRTC needs some way to **exchange connection info** (IP, codec, encryption keys).  
   - Typically done with **SIP over WebSockets**, WebSocket JSON, or custom APIs.  
   - Asterisk or FreeSWITCH can act as the signaling server.

4. **NAT Traversal (STUN/TURN)**  
   - Most users are behind NAT routers, so direct P2P is tricky.  
   - **STUN server**: tells the client its public IP/port (free servers exist).  
   - **TURN server**: relays media if NAT/firewall blocks direct traffic.  
   - Example: Google provides a free STUN server `stun.l.google.com:19302`.

5. **Encryption** (mandatory)  
   - All WebRTC traffic is encrypted by design.  
   - **DTLS-SRTP** for media (voice/video).  
   - **TLS** for signaling.  
   - This is why WebRTC is considered more secure than plain SIP/UDP.

---

# 🔹 How a WebRTC Call Works (Step by Step)
Let’s say Alice calls Bob through a WebRTC-enabled PBX (Asterisk):

1. **Alice’s browser/app gets mic/cam.**  
   → Generates an “offer” (SDP: codecs, IP, encryption info).  

2. **Signaling exchange (via PBX).**  
   → Alice’s browser sends offer → PBX → Bob’s browser.  
   → Bob generates “answer” (his own codecs/IP/etc) → sent back.  

3. **ICE candidate gathering.**  
   → Both sides collect possible network paths (LAN, public IP, TURN relay).  

4. **Connection setup.**  
   → They negotiate best route (direct if possible, via TURN if not).  

5. **Encrypted media starts.**  
   → Audio/video flows directly peer-to-peer if possible.  
   → PBX may stay in the path (if using it as media relay, e.g., for recording or transcoding).

---

# 🔹 Why WebRTC is Special
✅ **Browser native** – no plugins or installs.  
✅ **Secure by default** – encryption is mandatory.  
✅ **Flexible signaling** – can use SIP, custom JSON, or anything.  
✅ **Cross-platform** – works on Chrome, Firefox, Safari, Edge, Android, iOS.  
✅ **Data channels** – can send arbitrary data (chat, files, IoT signals) alongside audio/video.

- Then, a user can open a WebRTC client (e.g., a webpage with SIP.js or JSSIP) and dial extensions.

## 🔹 Does Asterisk understand Python/JSON directly?
Not natively.  
Asterisk itself is written in C and uses its own **dialplan language** (extensions.conf) and **AMI/ARI interfaces**. But you can **control Asterisk with Python** by using those APIs:

1. **Asterisk Manager Interface (AMI)**  
   - A TCP-based interface for events & commands.  
   - You can write a Python script that connects to AMI and issues commands (originate call, hangup, etc).  
   - Example Python libs:  
     - [`pyst2`](https://pypi.org/project/pyst2/)  
     - [`starpy`](https://pypi.org/project/starpy/)

2. **Asterisk REST Interface (ARI)**  
   - Modern JSON/REST API.  
   - Perfect for apps that want fine control over calls, bridges, channels, media.  
   - You send/receive **JSON over HTTP/WebSockets**.  
   - Example Python libs:  
     - [`asterisk-ari`](https://pypi.org/project/asterisk-ari/)  
     - `ari-py` (by Asterisk devs).

3. **AGI (Asterisk Gateway Interface)**  
   - Lets you run external scripts (Python, Perl, Bash) during a call.  
   - The PBX hands off control of the call flow to your script.  
   - Your Python script can read/write JSON, access DBs, etc.  

---

## 🔹 Where WebRTC fits in
- **WebRTC support is built into Asterisk (via PJSIP)**.  
- Your Python script doesn’t need to “handle” WebRTC itself.  
- Instead:  
  - **Asterisk handles SIP-over-WebSocket, DTLS-SRTP, STUN/TURN**.  
  - Your Python script (via ARI/AMI/AGI) can dynamically control **what happens to the call** (e.g., who to connect to, record call, play audio).  

---

## 🔹 Example Flow
1. Browser client (WebRTC, e.g., SIP.js) registers to Asterisk (PJSIP).  
2. User clicks “Call” → Asterisk creates a new channel.  
3. Your **Python script via ARI** gets an event in JSON:  
   ```json
   {
     "type": "StasisStart",
     "channel": {
       "id": "12345678",
       "caller": { "number": "1001" }
     }
   }
   ```
4. Your Python app decides what to do: bridge two channels, play an announcement, route to voicemail, etc.  
5. The Python app sends JSON commands back to Asterisk over ARI:  
   ```json
   {
     "action": "Bridge",
     "channels": ["12345678", "87654321"]
   }
   ```
6. Asterisk executes → browser clients are now connected.

✅ You can write your **business logic in Python**.  
✅ Asterisk just handles the **heavy lifting of SIP/WebRTC/media**.  
✅ JSON/REST makes it clean to integrate with modern web apps.  
✅ Future-proof — you can later add billing, CRM integration, AI transcription (using Python libs) without touching the PBX core.

# 🔹 Step 3. Python ARI Script (Bridge Calls Automatically)

Install Python lib:
```bash
pip3 install asterisk-ari
```

Save as `bridge_app.py`:
```python
import ari
import logging
import time

logging.basicConfig(level=logging.INFO)

# Connect to Asterisk ARI
client = ari.connect(
    "http://localhost:8088",
    "ari_user",
    "mysecret"
)

bridges = {}

def stasis_start_cb(channel_obj, event):
    channel = channel_obj.json
    caller = channel['caller']['number']
    logging.info(f"New call from {caller}, channel id {channel['id']}")

    # Put channel into a bridge
    if "webrtc_bridge" not in bridges:
        bridge = client.bridges.create(type='mixing')
        bridge_id = bridge.id
        bridges["webrtc_bridge"] = bridge
        logging.info("Created new bridge")
    else:
        bridge = bridges["webrtc_bridge"]

    # Answer call and add to bridge
    channel_obj.answer()
    bridge.addChannel(channel=channel['id'])
    logging.info(f"Added {caller} to bridge {bridge.id}")

client.on_event("StasisStart", stasis_start_cb)

# Keep app alive
while True:
    time.sleep(1)
```

Run it:
```bash
python3 bridge_app.py
```

# 🔹 1. What is Linphone?
- **Linphone** is a **free, open-source SIP softphone**.

# 🔹 2. What is WebRTC?
- **WebRTC** is a web standard for **real-time audio/video/data** inside browsers and apps.  
- It uses **ICE/STUN/TURN** to handle NAT/firewalls.  
- Supports **secure media (SRTP/DTLS)**.  

👉 It’s NOT a PBX by itself — it’s just the **transport & media layer**.  
👉 You still need a **signaling server** (like SIP via Asterisk or Linphone’s Flexisip server).  

---

# 🔹 3. What is a PBX?
- **PBX = Private Branch Exchange**.  
- A server (like **Asterisk**, **FreeSWITCH**, or **3CX**) that manages:
  - **Extensions** (internal numbers like `1001`, `1002`)  
  - **Call routing** (who can call who)  
  - **Voicemail, IVR, conferencing**  
  - **Bridges/WebRTC gateways**  

👉 Without a PBX, two SIP/WebRTC clients can still connect directly — but then you lose call routing, extensions, voicemail, etc.  

---

# 🔹 4. Linphone + WebRTC + PBX

Here’s how they fit together:

```
[ Linphone app ] <-- SIP/WebRTC --> [ PBX (Asterisk/FreeSWITCH/Flexisip) ] <-- SIP/WebRTC --> [ Browser or Linphone ]
```

### Example:
1. You install **Linphone** on your PC/Phone.  
2. You configure it with:
   - SIP server: `127.0.0.1` (if PBX is local)

4. PBX routes call `1001 → 1002`.

# 🔹 5. Linphone Without PBX
- Linphone can call **direct SIP URIs** like:
  ```
  sip:1002@192.168.1.5

  if both devices are on the same LAN.  
- This bypasses a PBX.  
- But: you lose features (voicemail, conference, call rules).

- Linphone team built **Flexisip** → a SIP server with **WebRTC built-in**.  
- Acts like a PBX, optimized for Linphone clients.

If you want **full control**, you use Asterisk:
- Linphone = client (SIP softphone).

        r = requests.post(f"{PBX_URL}/api/extensions", json=payload, auth=(PBX_ADMIN, PBX_PASSWORD))
        if r.status_code in [200,201]:
            print(f"Extension {ext_info['ext']} created successfully.")
        else:
            print(f"Failed to create {ext_info['ext']}: {r.text}")
    except Exception as e:
        print(f"Error creating extension {ext_info['ext']}: {e}")

def launch_linphone(ext_info):
    """Launch Linphone with pre-configured SIP account"""
    if not os.path.exists(LINPHONE_PATH):
        print(f"Linphone executable not found at {LINPHONE_PATH}")
        return
    # Linphone CLI options for auto-login
    args = [
        LINPHONE_PATH,
        f"--identity sip:{ext_info['ext']}@127.0.0.1",
        f"--password {ext_info['password']}",
        "--no-gui"  # optional if you want headless, remove to show GUI
    ]
    subprocess.Popen(args)
    print(f"Launched Linphone for {ext_info['ext']}")

# ======= Main Launcher =======
def main():
    print("VoIP Launcher starting...")
    # Step 1: create extensions
    for ext in EXTENSIONS:
        create_extension(ext)
        time.sleep(1)  # small delay

    # Step 2: launch Linphone clients
    for ext in EXTENSIONS:
        launch_linphone(ext)
        time.sleep(1)

    print("All done. You can now call between extensions.")

if __name__ == "__main__":
    main()
```

# 🔹 2. Server.py (Chat Server)

```python
import asyncio
import websockets
import json

PORT = 8765
clients = {}  # {username: websocket}

async def handler(ws):
    try:
        async for message in ws:
            data = json.loads(message)
            target = data.get("target")
            text = data.get("text")
            sender = data.get("sender")
            
            if target == "ALL":
                # Broadcast
                for user, client_ws in clients.items():
                    if client_ws != ws:
                        await client_ws.send(json.dumps({"sender": sender, "text": text}))
            else:
                # Direct message
                if target in clients:
                    await clients[target].send(json.dumps({"sender": sender, "text": text}))
    except:
        # Remove disconnected client
        for user, client_ws in list(clients.items()):
            if client_ws == ws:
                del clients[user]
                break

async def register(ws):
    await ws.send("USERNAME?")
    username = await ws.recv()
    clients[username] = ws
    print(f"{username} connected.")
    await handler(ws)

async def main():
    async with websockets.serve(register, "127.0.0.1", PORT):
        print(f"Server started on port {PORT}")
        await asyncio.Future()  # run forever

if __name__ == "__main__":
    asyncio.run(main())
```
