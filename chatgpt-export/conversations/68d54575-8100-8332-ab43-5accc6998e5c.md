## 1️⃣ What is a mesh network?

A **mesh network** is a network topology where **every device (node) can connect to multiple other devices**, rather than going through a central hub or router.  

**Key idea:**  
- Each node can **relay data** for other nodes.  
- If one node fails or goes offline, the network automatically reroutes traffic through other nodes.  
- This makes mesh networks **resilient, flexible, and scalable**.  

---

## 2️⃣ How it works

1. **Nodes:** Each device (radio, smartphone, sensor, Wi-Fi hotspot) acts as a node.  
2. **Routing:** Data finds the best path to its destination, hopping from node to node if necessary.  
3. **Self-healing:** If one node drops, the network automatically finds a new path.  
4. **Peer-to-peer:** No single “server” is required — each node helps maintain connectivity.  

---

### Simple Example

Imagine 5 nodes: A, B, C, D, E  

```
A — B — C
|         |
D — E — C
```

- Node A wants to send a message to E.  
- The message can hop A → D → E or A → B → C → E.  
- If node B goes offline, the message still reaches E through the D → E path.  

---

## 3️⃣ Applications

1. **Wi-Fi Mesh Routers:**  
   - Example: Google Nest Wi-Fi, Netgear Orbi.  
   - Extend Wi-Fi in large homes without running Ethernet cables.  

2. **Military / Emergency Networks:**  
   - Radios form ad-hoc mesh so units stay connected in remote areas.  

3. **IoT (Internet of Things):**  
   - Sensors communicate over a mesh to relay data back to a central hub.  

4. **Amateur Radio Mesh Networks:**  
   - Example: **HSMM-Mesh** or **APRS digipeaters**.  
   - Radios or nodes relay messages over VHF/UHF bands.  
   - Can carry text messages, GPS, or limited digital data without Internet infrastructure.  

---

## 4️⃣ Advantages

- **Self-healing:** network adapts if nodes fail.  
- **Scalable:** add nodes without redesigning the network.  
- **Flexible range:** nodes extend coverage without repeaters.  
- **Redundant paths:** more than one path between points.  

---

## 5️⃣ Limitations

- **Bandwidth:** each hop can reduce throughput.  
- **Latency:** more hops = more delay.  
- **Complex routing:** requires smart protocols to manage paths.  
- **Power:** each node relays traffic, so battery-operated nodes may drain faster.  

---

A **mesh network** is essentially a **cooperative, peer-to-peer network** where devices help each other communicate. For amateur radio or private digital systems, it allows **long-range communication without a central repeater**, because each node relays messages to extend coverage.

## PHASE 5 — Create encrypted site-to-site network (WireGuard)
WireGuard gives a small, easy VPN tunnel between sites. We’ll set up a central WireGuard server and connect each site as a peer. **All voice traffic will run through this encrypted tunnel.**

### On the central server (Debian/Ubuntu example)
1. Install WireGuard:
```
sudo apt update
sudo apt install -y wireguard iproute2
```
2. Generate keys:
```
wg genkey | tee server_privatekey | wg pubkey > server_publickey
```
3. Create `/etc/wireguard/wg0.conf` (example):
```
[Interface]
Address = 10.255.0.1/24
ListenPort = 51820
PrivateKey = <contents of server_privatekey>
SaveConfig = true
```
4. Start WireGuard:
```
sudo wg-quick up wg0
sudo systemctl enable wg-quick@wg0
```

### On a Site client (e.g., siteA)
1. Install and generate keys same as above but name them client_private/public.
2. Example `wg0.conf` on client:
```
[Interface]
Address = 10.255.0.10/24
PrivateKey = <client_privatekey>

[Peer]
PublicKey = <server_publickey>
Endpoint = <server_public_ip_or_domain>:51820
AllowedIPs = 10.255.0.0/24
PersistentKeepalive = 25
```
3. On server add peer (either edit server wg0.conf or use `wg set`):
```
[Peer]
PublicKey = <client_publickey>
AllowedIPs = 10.255.0.10/32
```
4. Bring client up:
```
sudo wg-quick up wg0
```

> Repeat for each site with distinct `Address` (10.255.0.11, .12, ...). Now all sites can reach each other on the 10.255.0.0/24 network — encrypted.

```
sudo sysctl -w net.ipv4.ip_forward=1
```

# How privacy / one-to-one works (conceptual)
- Every user has:
  - A unique **UserID** (UUID or numeric extension)
  - A private **session key** (symmetric AES key) — used to encrypt the voice/data stream
- Call flow (1-to-1):
  1. Caller finds callee’s online presence (broadcast or via local directory).
  2. Caller and callee establish a session key (pre-shared or via Diffie-Hellman handshake).
  3. Voice/data packets are encrypted and sent as UDP to the callee’s IP:port. Only callee with the key can decrypt.
- Others on the same channel may **see** encrypted packets but cannot decrypt them.

### `scan_and_link.py` (single file, minimal)
```python
#!/usr/bin/env python3
"""
Simple demonstration:
- Scans Wi-Fi (2.4/5 GHz) channels (via pywifi)
- Picks a least-crowded channel (based on SSID counts)
- Then runs a simple encrypted UDP sender/receiver on chosen port.
Use pre-shared AES key for encryption.
"""
import time, socket, threading, uuid
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
from Crypto.Random import get_random_bytes

try:
    import pywifi
    from pywifi import const
except Exception as e:
    pywifi = None
    print("pywifi not available. Scanning disabled. Run only UDP link part.")

# ---------- config ----------
AES_KEY = b'ThisIs32ByteAESKeyForDemoPurps!!'  # 32 bytes for AES-256 (replace with secure random)
UDP_PORT = 40000
BIND_IP = '0.0.0.0'   # listen on all interfaces
# ----------------------------

def aes_encrypt(key, plaintext):
    iv = get_random_bytes(16)
    cipher = AES.new(key, AES.MODE_CBC, iv)
    ct = cipher.encrypt(pad(plaintext, 16))
    return iv + ct

def aes_decrypt(key, data):
    iv = data[:16]
    ct = data[16:]
    cipher = AES.new(key, AES.MODE_CBC, iv)
    pt = unpad(cipher.decrypt(ct), 16)
    return pt

def udp_receiver(key, bind_ip, port):
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.bind((bind_ip, port))
    print(f"[UDP] Listening on {bind_ip}:{port}")
    while True:
        data, addr = s.recvfrom(65535)
        try:
            pt = aes_decrypt(key, data)
            print(f"[{addr}] {pt.decode(errors='ignore')}")
        except Exception as e:
            print(f"[{addr}] Received non-decryptable packet or error: {e}")

def udp_sender_once(key, target_ip, port, message):
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    ct = aes_encrypt(key, message.encode())
    s.sendto(ct, (target_ip, port))
    s.close()

def scan_wifi_and_pick_channel():
    if pywifi is None:
        print("pywifi not installed or unavailable on this platform.")
        return None
    wifi = pywifi.PyWiFi()
    iface = wifi.interfaces()[0]
    iface.scan()
    time.sleep(2)
    results = iface.scan_results()
    # Count by channel (pywifi gives frequency in MHz)
    ch_count = {}
    for r in results:
        freq = r.freq
        ch = freq_to_channel(freq)
        ch_count[ch] = ch_count.get(ch, 0) + 1
    # For 2.4 GHz channels 1..11; for 5 GHz many channels
    # pick channel with minimal count
    if not ch_count:
        print("No networks found.")
        return None
    best = min(ch_count.items(), key=lambda x: x[1])
    print("Channel counts:", ch_count)
    print("Picked channel:", best[0], "with", best[1], "networks")
    return best[0]

def freq_to_channel(freq_mhz):
    # 2.4 GHz channels:
    if 2401 <= freq_mhz <= 2483:
        return int((freq_mhz - 2407) / 5)
    # 5 GHz (very simple mapping for common channels)
    return int(freq_mhz / 5)

if __name__ == "__main__":
    # Start receiver thread
    recv_thread = threading.Thread(target=udp_receiver, args=(AES_KEY, BIND_IP, UDP_PORT), daemon=True)
    recv_thread.start()

    print("Unique device ID:", uuid.uuid4())

    # Optional: scan wifi and pick channel
    ch = scan_wifi_and_pick_channel()
    if ch:
        print("NOTE: you must set your AP or phone to use that channel. This script only scans and recommends.")

    # Simple CLI to send messages
    print("Type 'send <IP> <message>' to send encrypted UDP message.")
    while True:
        try:
            line = input("> ").strip()
            if not line: continue
            if line.lower() == "exit": break
            if line.startswith("send "):
                parts = line.split(" ", 2)
                if len(parts) < 3:
                    print("Usage: send <IP> <message>")
                    continue
```

# RFID — quick, clear explainer (and what you can do with “RFID code”)

Short answer: **RFID = radio IDentification**. It’s intended for identifying objects and exchanging *very small* amounts of data (IDs, tiny records). It is **not** a replacement for Wi-Fi/LoRa/VoIP — you can’t use RFID for voice or large data transfer. Below I’ll cover types, frequencies, common standards (the “codes”), ranges/limits, how to read/write tags (including smartphone options), security/privacy, and a tiny Python example to get you started.

---

## 1) What RFID is
RFID systems consist of:
- **Tags** (passive or active) attached to objects. They hold an ID and sometimes small user memory.
- **Readers** (interrogators) that power/read/write passive tags or talk to active tags.
- **Antenna** for the RF link.

RFID ≠ NFC, but NFC is part of the RFID family (NFC is HF RFID 13.56 MHz with extra handshake behaviors and phone support).

---

## 2) Main RFID frequency bands & characteristics

| Band | Frequency | Typical range | Typical use |
|------|-----------:|---------------:|-------------|
| LF | 125–134 kHz | ~1–10 cm | Animal tags, access keys |
| HF | 13.56 MHz | ~1–30 cm | NFC, smartcards, library cards, ISO 14443 / 15693 |
| UHF | 860–960 MHz (EPC Gen2) | ~1–12 m (passive), further with active tags | Inventory, logistics, supply chain |
| Microwave | 2.45 GHz etc. | similar to UHF | Some specialized systems |
| Active tags | various (battery powered) | tens to hundreds of meters | Asset tracking with telemetry |

---

## 3) Common protocols / “codes” (standards)
- **ISO 14443** (Type A/B) — NFC, contactless payment cards, passports (very short range).  
- **ISO 15693** — vicinity cards, read range greater than 14443.  
- **EPC Gen2 / ISO 18000-6C** — UHF passive tags for logistics (EPC = Electronic Product Code).  
- **EM4100 / EM4102** — simple LF tags with fixed ID.  
- **ISO 18092 / NFC Forum** — NFC peer-to-peer and tag formats (NDEF).  

When people say “RFID code” they often mean the **tag’s unique identifier (UID or EPC)** or the tag’s stored payload (e.g., an NDEF record on NFC).

---

## 4) Data capacity & bandwidth
- Typical payloads: a few bytes (UID) up to a few kB (some HF tags) — **very small**.  
- UHF EPC tag typically stores an EPC string (96–256 bits) plus possibly small user memory (a few bytes to a few hundred bytes).  
- **Not suitable for voice or streaming data**. Use RFID for IDs, tiny sensor reports, or to bootstrap a connection (e.g., tap phone to tag to get a URL).

---

## 5) Range limits & real-world performance
- LF/HF (NFC) → **centimeters**. Great for secure tap actions and smartphones.  
- UHF passive → **meters**, line-of-sight, affected by orientation, materials (metal/liquid interfere).  
- Active tags (battery) → **tens to hundreds of meters**.

---

## 6) Can RFID/NFC be used with smartphones?
- **Yes — NFC (13.56 MHz)** is supported by most Android phones (and some iPhones with restrictions). You can read/write NFC tags and use NFC peer-to-peer for tiny payloads.
- **UHF RFID**: phones do not have built-in UHF. You need an external UHF RFID reader (Bluetooth or USB) to connect to a phone.
- Typical smartphone use cases:
  - Tap a tag to open a URL, pair a device, exchange a contact, or retrieve a short ID.
  - Use a phone app to read/write NDEF records (text, URIs, small vCard, small config).

---

## 7) Security & privacy
- **UIDs are not secret.** Anyone with an RFID reader can read passive tag IDs in range.  
- **Cloning:** many low-cost tags are clonable; use secure tags (cryptographic tags) for authentication.  
- **Secure options:** ISO 14443A variants with mutual authentication, MIFARE DESFire (supports AES/3DES), some UHF tags support signed/EPC cryptographic options.
- **NFC payments and passports** use cryptographic protections — don’t assume all tags are secure.
