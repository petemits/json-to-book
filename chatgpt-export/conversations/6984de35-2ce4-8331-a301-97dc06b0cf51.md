## Why it’s not truly “portable”
Asterisk is not a standalone `.exe`. It needs:
- A **Linux OS** (recommended)
- System libraries (glibc, DAHDI, PJSIP, etc.)
- Network access + ports
- Sometimes kernel modules (for telephony hardware)

So you **cannot** just plug a USB into *any random computer* (especially Windows) and double-click Asterisk.

---

## What *does* work (best options)

### ✅ **Option 1: Bootable Linux USB with Asterisk (BEST & CLEANEST)**
This is the closest thing to “run on any computer”.

**How it works**
- USB contains:
  - Linux OS (Ubuntu Server / Debian)
  - Asterisk installed
- You boot the computer **from USB**
- The host computer’s OS is untouched

**Pros**
- Works on almost any PC
- No install on host machine
- Stable & professional
- Used in real deployments

**Cons**
- Requires reboot
- Needs BIOS/UEFI boot access

**Typical stack**
- Debian minimal
- Asterisk
- FreePBX (optional GUI)

---

### ✅ **Option 2: Portable Virtual Machine on USB**
Asterisk runs *inside* a VM stored on USB.

**How it works**
- USB contains:
  - VirtualBox portable
  - Linux VM with Asterisk
- Host computer must allow virtualization

**Pros**
- No reboot
- Works on Windows/Linux hosts

**Cons**
- Slower
- Needs admin rights
- VirtualBox must be allowed

---

### ⚠️ **Option 3: Run from USB on existing Linux**
You can install Asterisk binaries and configs on USB and run them on any Linux PC.

**Reality check**
- Same Linux distro & architecture required
- Libraries must match
- Not reliable across random machines

This is more for **your own machines**, not “any computer”.

---

## What does NOT work
❌ Running Asterisk directly on Windows from USB  
❌ Plug-and-play on locked corporate computers  
❌ No-admin environments  
❌ Phones working without network permissions

## What WebRTC actually is
**WebRTC** lets audio/video calls run **directly inside a browser**  
(no plugins, no softphone install).

It uses:
- **SRTP** (encrypted media)
- **DTLS**
- **ICE / STUN / TURN** (NAT traversal)
- **Opus codec**

Think of it as **SIP for browsers**, but modern and secure.

---

## How WebRTC works with Asterisk
Browser **does NOT talk SIP directly**.

Flow:
```
Browser (WebRTC)
   ↓  (WSS + SRTP)
Asterisk (PJSIP)
   ↓
SIP Phones / PSTN / Trunks
```

Asterisk acts as:
- SIP ↔ WebRTC gateway
- Media relay
- Call controller

---

## What you need (minimum)
### Server
- Linux (VM, cloud, or bare metal)
- Asterisk 16+ (18 LTS or 20 recommended)
- Public IP or proper NAT rules
- SSL certificate (mandatory)

### Browser
- Chrome / Firefox / Edge
- Mic permission allowed

---

## Required Asterisk settings (conceptual)

### 1️⃣ Enable secure transport
WebRTC **requires WSS**
```
HTTPS (TCP 443)
WSS (WebSocket Secure)
```

### 2️⃣ Create a WebRTC SIP endpoint
Key requirements:
- `transport=wss`
- `media_encryption=dtls`
- `dtls_auto_generate_cert=yes`
- `ice_support=yes`
- `use_avpf=yes`
- `rtp_symmetric=yes`
- `rewrite_contact=yes`

---

### 3️⃣ Enable codecs
WebRTC uses:
- **Opus** (preferred)
- G.711 (fallback)

Asterisk must have **Opus installed**.

---

## Ports you must open
```
443  → HTTPS / WSS
10000–20000 → RTP media
```

If behind NAT → STUN/TURN required.

---

## Client side (browser)
You can use:
- **JsSIP** (most popular)
- SIP.js
- SimpleWebRTC

Browser connects like:
```
wss://pbx.yourdomain.com/ws
```

---

## Simple mental model
- SIP phone → uses UDP/TCP
- WebRTC phone → uses **WSS + SRTP**
- Asterisk connects both worlds

---

❌ No Opus → call fails  
❌ Using ws instead of wss  
❌ Firewall blocking RTP

   ```
   cd asterisk-20.*
   ./configure
   make
   sudo make install
   sudo make samples
   sudo make config
   ```
5. Start Asterisk:  
   ```
   sudo systemctl start asterisk
   sudo systemctl enable asterisk
   ```
